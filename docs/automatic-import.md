# 自動取り込みとcapture単体からの再生成

## 利用方法

音楽CDを挿入し、`mise run import`を実行する。
光学メディアを検出して取り込み、曲情報を照合し、`~/Music/diskflow/日時-識別子/`へ保存する。
CDが複数ある場合は番号で選択する。デバイス名やAppleアルバムIDの入力は通常不要。

曲情報はMusicBrainzのDisc IDを使う。未登録ならmacOSのボリューム名・曲名からAppleを検索し、
曲数・曲順・全曲の長さをTOCと比較する。取得できた曲名も照合する。
候補が複数ある場合は勝手に決めず、端末で選択する。検索に使える名前がない場合はアルバム名などの入力を求める。
未登録・表記の相違・情報不足で自動取得できない場合もあり、TOCだけで必ず曲名を特定できる仕組みではない。

カバーを用意する場合は、プロジェクトルートに`cover.jpg`または`cover.png`を1枚置く。
`--artwork`で別の画像を指定することもできる。画像がなければDB画像を使うが、通常盤・初回盤との一致は未確認と記録する。
再生成では保存済みカバーを優先し、無関係な作業ディレクトリの画像へ切り替えない。

## 残すファイル

```text
<output>/
  aac/                  完成品のM4A・曲情報・カバー・タグ検証記録
  capture/              未加工音声・TOC/CUE・読み取り記録
    metadata/           曲情報・カバー・照会結果
    recipe.json         再生成条件・環境・ファイルハッシュ
  logs/                 工程別の検証記録（成功後は作業音声なし）
  report.json           全体結果、schema_version: 2
```

WAV、音量調整済みWAV、タグ設定前AACは作業中に必要だが、成功時には残さない。
完成品・原本・レポートを検証した後、今回の出力に生成された音声だけをハッシュ確認して削除する。
以前の出力やコピー元は変更しない。失敗時は中間ファイルを残す。

YouTube Musicへ渡すのは`aac/`の`.m4a`。
[公式のアップロード対応形式](https://support.google.com/youtubemusic/answer/9716522?hl=ja)にもM4Aが含まれる。
保存用には`capture/`全体を保持する。アップロード自体は`shortcuts_app`側で扱う。

## CDなしで再生成

```sh
mise run import -- "/保存したアルバム/capture"
```

新形式のcaptureには、未加工音声だけでなく曲情報・カバー・正規化条件・AAC設定・環境情報も保存する。
曲情報と画像をネットから取り直さずに使い、ハッシュ不一致では停止する。
再生成には対応するmacOSとPython依存パッケージなどの実行環境が必要。
原本PCMは同じデータを使えるが、ディザやAppleエンコーダーの変更により、M4Aのバイト一致は保証しない。
古いイメージだけのcaptureには曲名や画像がなく、別途照合・入力が必要になる。

## 2026-10-22の検証

旧形式の保存済みアルバムから、新形式の出力を生成した。元の曲情報・初回限定盤共通カバーは再利用した。

```sh
mise run import -- artifacts/import-20261021-231336 \
  --output artifacts/compact-20261022-230933 --non-interactive
```

続いて、`artifacts/compact-20261022-230933/capture`だけを入力にもう一度生成した。
再生成の検証ではメタデータ通信とCDアクセスの関数を例外を返すものへ置き換え、
それらを呼ばなくても、実際のAppleエンコーダーで全13曲を生成できることを確認した。
出力先は`artifacts/rebuilt-20261022-231317/`。

両方でWAVとタグ設定前AACは残らず、M4Aは`aac/`に13曲だけ存在した。
全工程・全成果物のハッシュ、曲名・カバー、タグ付け後のAAC署名、標準出力JSONと保存レポートの一致を確認した。
原本音声のSHA-256は従来の値と一致した。

```text
974dd6e640a3bdee382e62929119810bbf0df52bfcb15d2f3c39d742ccf7f6b9
```

今回の完成M4Aは約120 MB、保存用captureは約632 MB。
デコード後のLUFSは−14.031〜−14.009、最大True Peak上側推定値は約−2.963 dBTPで、全曲が目標判定を満たした。
確認結果はそれぞれの出力先の`validation-summary.json`に保存した。取得物はGit管理対象外。

Appleの自動検索も、以前保存した実CDのボリューム名・曲名を検索ヒントにして実APIで確認した。
アルバムIDを指定せずaiko『最後に熱い日々を狂わしき想いで』全13曲に照合でき、時間差は最大約0.333 msだった。
記録は`artifacts/metadata-auto-20261022-230934/`。

全285テスト、Ruff、miseのタスク定義検証、uvのロック確認、シェル構文チェックが通った。
CD自動検出からの物理読み取りはモックで確認したが、今回の実機検証は保存済みイメージによるもの。
実CDでの自動一括取り込みと全曲PCM比較、独立した読み取り品質の検証は別途必要。
`archival_verified`は引き続き`false`とする。
