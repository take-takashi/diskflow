# 一括処理の検証

この文書は2026-10-21時点の初期版（全体レポートv1）の記録。
現在の自動検出・完成品AAC・capture単体からの再生成は[自動取り込みと再生成の検証](automatic-import.md)を参照。

## 対象

2026-10-21、miseの`import`タスクを追加した。
`mise-tasks/import`の`#USAGE`で引数と日本語ヘルプを定義し、
パースされた`usage_*`環境変数を`diskflow.workflow`へ渡す。
シェルのコマンド文字列へユーザー入力を展開せず、Pythonから既存の処理関数を順番に呼び出す。
追加のツールやPython依存パッケージは導入していない。

対象はCD読み取りからローカル出力まで。Notionへの保存は`shortcuts_app`側の責務とし、実装していない。
既存の工程別コマンドも変更せず残している。

## 実行したコマンド

保存済みの13曲のイメージと、取得済みの初回限定盤共通カバーを使った。
CDの再読み取りは行っていない。

```sh
mise run import -- --capture artifacts/rip-20261020-231010 \
  --output artifacts/import-20261021-231336 \
  --artwork artifacts/metadata-limited-20261021-144903/cover.jpg \
  --edition "初回限定盤（A/B共通ジャケット）" --apple-album-id 6813318544 \
  > artifacts/import-20261021-231336.stdout.json
```

この出力先は取得済みなので、再実行時は新しい名前に変える。
原本のコピー、曲情報取得、WAV切り出し、Track Gain、Apple AAC変換、タグ付けの全工程が成功した。
全体レポートの開始から終了まで約85.6秒。最終M4A全13曲の合計サイズは120,093,842バイト。
全曲がLUFS目標の判定を満たし、Apple AACのfloat32デコード後のTrue Peak検証も通った。

## 出力と保存後の確認

ルートの`report.json`と標準出力のJSONが一致した。
全工程のレポートハッシュと、最終M4A・カバー・アルバム情報・原本ファイルのサイズとハッシュを照合した。
タグ・版のラベル・画像をM4Aから再読し、タグ付け前後のAACパケット・コーデック設定・時刻情報も比較した。
全13曲で一致し、タグ付けで再エンコードしていないことを確認した。

コピー後の原本ファイルは入力と同一で、元のイメージも変更されていない。
音声イメージのSHA-256は次の値だった。

```text
974dd6e640a3bdee382e62929119810bbf0df52bfcb15d2f3c39d742ccf7f6b9
```

確認結果は`artifacts/import-20261021-231336/validation-summary.json`に保存した。
音声・画像・端末固有ログはGit管理対象外。

## レポートの扱い

- `schema_version: 1`、`operation: import`で一括処理のレポートを識別する。
- `output_directory`は実行時の出力先。`stages`と`result`のファイル参照はそのフォルダからの相対パス。
- `status: complete`のときだけ`result`に成果物一覧を設定する。失敗時は`result: null`にする。
- 各工程の状態・開始終了時刻・レポートハッシュを記録し、失敗時は後続工程を実行しない。
- `result.all_targets_reached`と処理全体の成否は別。ピーク制約などでLUFS目標に届かなくても、方針通りの処理は完了できる。
- `archival_verified: false`を維持する。一括処理の完了は独立したセキュアリッピングの保証ではない。

終了コードは成功0、失敗1、Ctrl-Cによる中断130。
引数や画像の不備はCDデバイスを開く前に検査する。Usageの解析エラーはmise側のエラーとして終了する。
処理開始後の失敗では出力を削除せず、完了済み工程と途中の証拠を残す。
途中再開と、既存出力フォルダへの上書きは実装していない。

## テスト範囲と制約

保存済みイメージからの一括処理、出力先の空白・日本語、相対パス参照、コピー元の不変性、
画像の開始時コピー、各工程の失敗・中断、入力の改変、成果物の改変、出力先外への参照拒否をテストする。
mise自体を起動するテストでは、Usageのヘルプ・必須フラグ・不明なフラグ・引数の受け渡しを確認する。
ネットワーク・Appleエンコーダー・CDデバイスは単体テストではモックし、上記の13曲では実際のAPIとAppleエンコーダーを使った。
全261テスト、Ruff、miseのタスク定義検証、uvのロック確認が通った。

`--device`の一括経路は、2回の読み取りを含めてモックで確認したが、実CDでの一括実行は未確認。
実CDでの全曲PCM比較、別条件での再読み取り、独立した読み取り品質の検証は引き続き別途必要。
